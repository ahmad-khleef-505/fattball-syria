# ملاعب سوريا

تطبيق Flutter لحجز ملاعب كرة القدم في سوريا، مع Firebase Authentication وCloud
Firestore وCloud Functions وCloud Storage وFirebase Cloud Messaging.

## المتطلبات

- Flutter وDart بإصدارات متوافقة مع القيود في `pubspec.yaml`.
- Node.js 20 وnpm لتطوير Cloud Functions.
- Firebase CLI، وFlutterFire CLI.
- مشروع Firebase مع تفعيل Authentication (Email/Password)، Firestore،
  Cloud Storage، Cloud Messaging، وCloud Functions.

## إعداد Firebase والتطبيق

1. أنشئ مشروع Firebase، وفعّل تسجيل الدخول بالبريد الإلكتروني وكلمة المرور.
2. اربط تطبيقات Android وiOS وWeb المطلوبة بالمشروع. استخدم **Project ID**
   (وليس الاسم الظاهر للمشروع) من إعدادات Firebase:

   ```powershell
   dart pub global activate flutterfire_cli
   flutterfire configure --project=YOUR_FIREBASE_PROJECT_ID --platforms=web,android,ios --out=lib/core/firebase_options.dart
   ```

   استبدل `YOUR_FIREBASE_PROJECT_ID` بمعرّف المشروع الحقيقي. يستبدل الأمر
   ملف `lib/core/firebase_options.dart` المؤقت الذي يستورده `main.dart`،
   ويسجّل إعدادات المنصات الثلاث المطلوبة. لا تترك قيم `REPLACE_WITH_...`.
3. أعد إعداد Flutter وشغّله:

   ```powershell
   flutter pub get
   flutter run
   ```

   ولتشغيل نسخة الويب في المتصفح:

   ```powershell
   flutter run -d chrome
   ```

4. لإشعارات Android، أضف إعدادات Firebase التي يولدها FlutterFire إلى تطبيق
   Android. لإشعارات iOS، فعّل Push Notifications وBackground Modes في
   إعدادات التطبيق، واربط مفتاح APNs في Firebase Console. يجب منح المستخدم
   إذن الإشعارات على الجهاز.
5. أنشئ Firestore وCloud Storage في Firebase Console. يستخدم المشروع منطقة
   `me-central1` لوظائفه، والمنطقة الزمنية `Asia/Damascus` للمهام المجدولة.

## المحاكيات المحلية

المنافذ معرفة في `firebase.json`: Authentication على 9099، Firestore على
8082، Functions على 5001، Storage على 9199، وواجهة المحاكيات على 4000.

تطبيق Flutter في الإعداد الحالي يتصل بمشروع Firebase الحقيقي فقط؛ لا توجد
وصلات محاكيات في `main.dart`. اختبارات التكامل تشغّل محاكياتها المعزولة تلقائياً
باستخدام `demo-integration`، ولا تتصل ببيانات المشروع الحقيقي.
اختر مشروعاً للنشر عبر `firebase use --add`، أو مرّر
`--project YOUR_FIREBASE_PROJECT_ID` إلى أوامر النشر أدناه.

## Cloud Functions والنشر

```powershell
Set-Location functions
npm ci
npm run build
npm run lint
Set-Location ..
firebase deploy --project YOUR_FIREBASE_PROJECT_ID --only firestore:rules,firestore:indexes,storage
firebase deploy --project YOUR_FIREBASE_PROJECT_ID --only functions
```

تتضمن الوظائف إنشاء الحجوزات دون تعارض، وانتهاء الاشتراكات يومياً، وإشعارات
تغيّر الحجوزات، وتذكير مالك الملعب قبل الموعد بنحو ساعة (تُفحص الحجوزات كل
خمس دقائق). يتطلب تشغيل المهام المجدولة تفعيل الفوترة وخدمات Cloud Scheduler
في مشروع Firebase. راجع سجلات Firebase Functions عند فشل النشر أو التشغيل.

### اختبارات التكامل للحجز والاشتراكات والمدربين

تتطلب Node.js وFirebase CLI. شغّل من مجلد `functions`؛ يستخدم الاختبار محاكيات
Auth وFirestore وFunctions على منافذ منفصلة، ولا يتصل بمشروع إنتاج:

```powershell
Set-Location functions
npm ci
npm run test:integration
```

يغطي الاختبار تفعيل الاشتراك وتسجيل `admin_logs`، صلاحيات إنشاء المدربين
وعرضهم، تسعير جلسة الطفل في الكتابة المباشرة والوظيفة السحابية، رفض السعر
المتلاعب به، منع تعارض المواعيد، وإيقاف الحجز بعد انتهاء الاشتراك أو تعطيل
المدرب. الإعداد المنفصل موجود في `firebase.integration.json`.

## المساعد الذكي

يستخدم المساعد Gemini من خلال callable Cloud Function في منطقة `me-central1`.
لا يُرسل مفتاح Gemini إلى تطبيق Flutter ولا يُحفظ في المستودع. لإعداده للإنتاج،
أنشئ مفتاحاً من Google AI Studio ثم خزّنه كسرّ Firebase؛ سيطلب الأمر القيمة
بشكل تفاعلي:

```powershell
firebase functions:secrets:set GEMINI_API_KEY --project YOUR_FIREBASE_PROJECT_ID
firebase deploy --project YOUR_FIREBASE_PROJECT_ID --only functions:chatAssistant
```

للتشغيل المحلي، أنشئ `functions/.secret.local` غير المتعقّب في Git واكتب فيه
`GEMINI_API_KEY=مفتاحك`، ثم شغّل Functions Emulator. لا تضع المفتاح في `--dart-define`
أو ملفات Flutter. تتطلب الخدمة مستخدماً مسجلاً، وتحدّ الاستخدام إلى 20 رسالة
يومياً لكل حساب بتوقيت دمشق. ترسل للمساعد بيانات مختصرة عن الملاعب المنشورة فقط؛
ولا يستطيع الاطلاع على حجوزات المستخدم الخاصة أو تنفيذ الحجز والإلغاء.

## الأكاديميات والمدربون

يستطيع صاحب الملعب إضافة مدربين لكل ملعب، وتحديد اختصاص كل مدرب ونبذته وأجر
التدريب بالساعة، وإخفاء المدرب مؤقتاً أو حذفه. يستطيع العميل اختيار مدرب متاح
من تفاصيل الملعب ثم حجز موعد للطفل (العمر 3–17 سنة). يحسب الحجز سعر الملعب وأجر
المدرب معاً، ويُراجع السعر وتوفر المدرب داخل معاملة الحجز وقواعد Firestore؛
وتبقى قيود منع تعارض المواعيد والعربون وكود الخصم مطبقة. يُحفظ الاسم الأول
للطفل وعمره ضمن سجل الحجز الخاص بالعميل وصاحب الملعب فقط.

## البطولات والطقس

- يستطيع مالك ملعب ذي اشتراك فعّال إنشاء بطولة وتحديد عدد الفرق (2–24)،
  ورسوم المشاركة والجوائز ومواعيد التسجيل والبطولة. يسجل الكابتن فريقاً واحداً
  بحسابه؛ الدفع نقداً أو عبر شام كاش/سيرياتيل كاش خارج التطبيق، وإثبات التحويل
  يُرفع إلى Storage ويبقى بانتظار اعتماد المالك. لا توجد بوابة تحصيل إلكتروني.
- بعد مراجعة جميع الطلبات واعتماد فريقين على الأقل، يغلق المالك التسجيل
  وينشئ التطبيق جدول دوري ذهاباً واحداً مع مواعيد المباريات، ويمكنه إضافة
  النتائج. توزّع المواعيد ضمن ساعات تشغيل الملعب بفاصل ساعتين، ويرفض النظام
  الجدول إذا لم تتسع فترة البطولة لجميع المباريات. الحد الأقصى 24 فريقاً
  لإبقاء إنشاء الجدول ضمن حدود Firestore Batch.
- تعرض واجهة العميل الطقس الحالي حسب المحافظة المختارة، وتتحقق من طقس ساعة
  الحجز حسب إحداثيات الملعب. تستخدم الخدمة Open-Meteo بلا مفتاح API، مع تخزين
  مؤقت للاستجابة 15 دقيقة. توقعات المواعيد البعيدة (أكثر من 15 يوماً) غير متاحة؛
  التنبيه توعوي ولا يلغي الحجز أو يغيّر موعده تلقائياً، ويجب تنسيق إعادة الجدولة
  مع صاحب الملعب.
- لوحة المجتمع تعرض بلاغات المفقودات/الموجودات وطلبات البحث عن فريق. يمكن
  إضافة صورة اختيارية، ويستطيع مالك الملعب المرتبط بالبلاغ الرد عليه؛ أما
  منشورات البحث عن فريق فتقبل ردود المجتمع المسجل. يستطيع ناشر بلاغ المفقودات
  تحديثه إلى «تم العثور عليه».

## حسابا الإدارة العليا

أنشئ ملف `.env.seed` في جذر المشروع بنسخة من `.env.seed.example`، واستخدم
كلمتي مرور مختلفتين وقويتين (12 محرفاً على الأقل). لا تضف الملف أو بيانات
اعتماد Admin SDK إلى Git. `.env.seed` مستثنى من `.gitignore`.

وفّر بيانات اعتماد Admin SDK عبر Application Default Credentials:

```powershell
gcloud auth application-default login
```

أو عيّن `GOOGLE_APPLICATION_CREDENTIALS` إلى ملف اعتماد محفوظ خارج المستودع.
ثم شغّل seed من مجلد `functions`:

```powershell
Set-Location functions
npm ci
npm run seed:admins
```

ينشئ السكربت أو يحدّث الحسابين التاليين ويمنحهما Custom Claims للإدارة العليا:

- محمد نور — `nurm41143@gmail.com`
- أحمد الخليف — `ahmadkhleefahmad@gmail.com`

غيّر كلمتي المرور فور أول تسجيل دخول. السكربت يضبط كلمة المرور من `.env.seed`
في كل تشغيل؛ حدّث القيم فيه قبل إعادة تشغيله، ولا تستخدم كلمات مرور حقيقية في
التوثيق أو الشيفرة.

## ملاحظات تشغيلية وأمنية

- قواعد Firestore وStorage موجودة في `firestore.rules` و`storage.rules`.
  الكتابات الإدارية الحساسة تمر عبر Cloud Functions وتتحقق من Custom Claims.
- رفع صور الملاعب محدود إلى الصور وبحجم أقصى 10 ميغابايت، ويتطلب اشتراكاً
  فعالاً. الصور العامة تُقرأ فقط عندما يكون الملعب منشوراً واشتراك مالكه فعالاً.
- يمكن للعميل اختيار عربون 20% نقداً أو عبر شام كاش/سيرياتيل كاش؛ يتطلب التحويل
  صورة إشعار، ويبقى الحجز بانتظار مراجعة المالك قبل التأكيد. لا يعالج التطبيق
  المدفوعات إلكترونياً. إثباتات التحويل محفوظة في Storage ومقيدة بالعميل والمالك.
- رقم واتساب الذي يضيفه المالك في نموذج الملعب اختياري ويظهر للعملاء كبيانات
  تواصل عامة؛ لا يُستخدم رقم الحساب الشخصي تلقائياً. الملاعب الموجودة مسبقاً
  تحتاج إلى تعديل بياناتها وإضافة الرقم يدوياً.
- التقييمات مرتبطة بحجز مكتمل، ويسمح بتقييم واحد لكل عميل في الملعب. تُخزّن
  كمراجعات عامة دون نشر رقم الهاتف أو الاسم الكامل للعميل.
- يستطيع مالك الملعب إنشاء أكواد خصم مرتبطة بملعبه بنسبة 1–90% وتاريخ انتهاء،
  وإزالة الكود لإيقافه. يتحقق التطبيق من صلاحية الكود داخل معاملة الحجز، وتتحقق
  قواعد Firestore من ملكية الكود ونسبته والسعر النهائي قبل قبول الحجز.
- تعرض لوحة المالك أرباح الحجوزات المكتملة وعددها خلال الشهر الحالي، ومخطط
  الأرباح المكتملة حسب أيام الأسبوع بتوقيت دمشق. نسبة الإشغال تقارن الحجوزات
  المؤكدة أو المكتملة (بما فيها المواعيد القادمة) بساعات تشغيل الملاعب الفعالة
  المتاحة خلال الشهر، مع مراعاة تاريخ انتهاء الاشتراك.
- تفعيل الاشتراك من لوحة الإدارة عملية إدارية يدوية وليست تحصيلاً إلكترونياً.
- لا تضع أسراراً أو كلمات مرور في ملفات Flutter أو ملفات التهيئة الملتزم بها.
- يجب إعداد Firebase فعلياً لكل منصة قبل التشغيل الكامل؛ ملف
  `lib/core/firebase_options.dart` هو Placeholder إلى أن يولّد FlutterFire
  إعدادات المشروع.
- ترسل إشعارات تغيّر حالة الحجز نغمة `football_whistle`. يشغل التطبيق ملف
  `assets/sounds/football_whistle.wav` عندما يكون مفتوحاً. لتشغيل النغمة من
  إشعارات Android بالخلفية، انسخ الملف إلى
  `android/app/src/main/res/raw/football_whistle.wav` وأنشئ قناة Android
  باسم `booking_updates` بهذه النغمة؛ إعداد القناة لا يتغير بعد إنشائها عادةً،
  لذا قد يلزم حذف القناة/إعادة تثبيت التطبيق لاختبار تعديلها. في iOS أضف
  الملف نفسه إلى هدف Runner في Xcode. هذا المستودع لا يتضمن حالياً مشروعي
  Android وiOS الأصليين، وإشعارات الويب لا تدعم النغمة المخصصة بهذه الطريقة.
